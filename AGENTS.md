# SleepPet — Expo SDK 54 / RN 0.81.5 (Android)

Read the exact versioned Expo docs at https://docs.expo.dev/versions/v54.0.0/ before writing code.

## CRITICAL: New Architecture must stay ON
- `newArchEnabled` is `true` in **both** `app.json` and `android/gradle.properties`.
- The app registers custom legacy native modules (`AccessibilityModule`, `NotificationModule`, `ReminderModule`, `MovementModule`, `SmartAlarmModule`) in `MainApplication.getPackages()`.
- If New Arch is disabled (Legacy mode), those modules are **not exposed to JS** → `NativeModules.AccessibilityModule` is `undefined` (JS warns "AccessibilityModule not found") and unlock/notification features silently stop working. Keep both flags `true`; `expo prebuild` syncs `app.json` → `gradle.properties`, so changing only one is not enough.

## Native code: two copies, keep in sync
- `plugins/native/java/com/gathod/SleepPet/` is the source of truth; `withSleepPetNative.js` (registered in `app.json` plugins) copies it to `android/app/src/main/java/...` on `expo prebuild`.
- Gradle compiles the `android/` copies. When editing any native `.kt`, edit **both** copies (they are byte-identical).
- `expo prebuild` wipes and regenerates `android/`, so manual edits there are lost unless mirrored in `plugins/`.

## Building & installing
- Build directly with Gradle (no prebuild): `cd android` then `gradlew assembleRelease` → APK at `android/app/build/outputs/apk/release/app-release.apk` (debug-signed via `app/debug.keystore`).
- Install: `adb install -r app\build\outputs\apk\release\app-release.apk`.
- **NUNCA ejecutar ningún Gradle build** — **siempre lo hace el usuario**. Los builds tardan minutos, consumen heap y no deben lanzarse sin permiso explícito del usuario (ni `assembleRelease` ni `assembleDebug` ni `prebuild`).
- `android/gradle.properties` `org.gradle.jvmargs=-Xmx4096m` (era 2048m) — el bundle 1383 módulos + VisionCamera native libs provoca `OutOfMemoryError: Java heap space` en `:app:packageRelease` con 2048m; tras OOM hacer `gradlew --stop` y reintentar.
- No test / lint / typecheck scripts exist.

## Unlock detection flow (native → JS)
- `UnlockAccessibilityService.kt` (accessibility service, enabled in Android settings) counts unlocks:
  - `ACTION_SCREEN_OFF` arms the counter.
  - `ACTION_USER_PRESENT` (Android's exact unlock signal) NO cuenta de inmediato: tras `FOREGROUND_CHECK_DELAY_MS` (800ms, tunable) resuelve `rootInActiveWindow.packageName` y llama `countUnlock(pkg)` — si el usuario quedó en SleepPet el filtro lo descarta (`Desbloqueo en SleepPet: no se cuenta`); `""` (transición sin ventana) cuenta por defecto. Antes se pasaba `""` siempre y TODO desbloqueo contaba aunque el usuario volviera a SleepPet.
  - `TYPE_WINDOW_STATE_CHANGED` of a real app remains the fallback for devices without keyguard (filtro SleepPet/systemui propio).
  - Decisión única por desbloqueo: armado se consume al resolver (quedarse en SleepPet no cuenta ahora ni cuentan navegaciones posteriores con la pantalla encendida). 2s debounce intacto; `handler.removeCallbacksAndMessages` en `onUnbind`/`onDestroy` limpia el chequeo diferido.
- It calls `AccessibilityModule.checkForegroundApp(pkg)` → filtra `com.gathod.SleepPet` y emite `PHONE_UNLOCKED` solo con paquetes distintos.
- `services/AccessibilityListener.js` subscribes; `context/AppContext.js` increments `unlockCount`/`unlockTimes` only while `sleepSessionStarted` is true.
- Session state persists via `services/SleepService.js` → `storage/CurrentSleepStorage.js`.
- Unlocks only count **after the screen turns off** (screen-off arms the counter).

## Foreground service
- `SleepForegroundService.kt` shows the persistent notification (elapsed time + unlock count). Usa `foregroundServiceType="specialUse|microphone"` (Fase B añade `microphone` para `AudioRecord`; antes solo `specialUse`) con `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` — do not revert a `health`; causó `SecurityException` en `startForeground`. `WAKE_LOCK` via `PowerManager.PARTIAL_WAKE_LOCK` 12h + `sensorKeepAliveRunnable` cada 120s (re-registra `TYPE_ACCELEROMETER` para evitar silencio `0 samples` visto a los 10m con `Doze`, `mWakefulness=Asleep` aun con `isForeground true`).
- **Movimiento nocturno (acelerómetro):** `MovementDetector` (clase interna del mismo servicio) captura `TYPE_ACCELEROMETER` (`SENSOR_DELAY_GAME ~50Hz`, sin permiso) mientras la sesión está activa; eventos con histéresis (tunables `MOVEMENT_START/END_THRESHOLD`, `MOVEMENT_QUIET_MS`, `MIN_MOVEMENT_DURATION_MS`, `MOVEMENT_COOLDOWN_MS` arriba del companion) + epochs de 5 min anclados a `startTime` + `movementScore` (exceso promedio sobre `MOVEMENT_NOISE_FLOOR`, no clínico). **Fase A Smart Sleep:** ventanas `SMART_WINDOW_MS 30000` (`SMART_MAX_WINDOWS 960 ~8h`) sincronizadas, `avg/max/avgExcess/samples` por ventana + recalibrado `LOW<0.93 MED<1.02` para `rsmzu8mztspndyj7` (baseline quieto `0.88-0.94` no `0.07`). Persistencia nativa en SharedPreferences `sleep_movement` (sobrevive muerte del proceso, incluye `smartWindows`); `MovementModule` (registrado en `MainApplication.getPackages()` + `PACKAGE_ADDS` de `withSleepPetNative.js`) expone `getMovementSummary`/`clearMovementSummary` — snapshot NO muta estado (poll 30s de SleepModeScreen no fragmenta epochs ni ventanas); `EXTRA_RESUME` (8º arg de `NotificationModule.startNotification`) distingue sesión nueva (limpia prefs) vs restore de `AppContext` (recarga y continúa). `finishSleep` lee el resumen tras `stopNotification`, lo guarda en `sleep_history` (`smartWindows` con `stage/confidence`) y limpia SIEMPRE. Docs completos en `ARCHITECTURE.md §6.6`.
- **Audio nocturno (Fase B):** `AudioRecord` `VOICE_RECOGNITION` `16kHz mono PCM16` en `HandlerThread SmartAudioThread` dentro del mismo servicio, ventana `30s` sincronizada con movimiento. Por ventana: `RMS = sqrt(mean(s²))` + `ZCR = cruces/samples` sobre `short[]` `1024` continuo, alimentado vía `MovementDetector.addAudioChunk(chunk)` y **descartado tras features** (no guarda archivo, `Arrays.fill` + GC). Si `RECORD_AUDIO` denegado (`ContextCompat.checkSelfPermission`) → `NO_AUDIO` fallback `accel-only` (sesión no se bloquea). Logs `SmartAudio` `rms/zcr` por ventana, `SleepModeScreen.handleStartSleep` pide `RECORD_AUDIO` tras `ACTIVITY_RECOGNITION` con `Alert` `micPermissionTitle/Message` (ES: *procesa local, descarta tras RMS/ZCR*). Permisos `RECORD_AUDIO` + `FOREGROUND_SERVICE_MICROPHONE` + `FOREGROUND_SERVICE_SPECIAL_USE` + `WAKE_LOCK` en `withSleepPetNative.js:9` y `android/app/src/main/AndroidManifest.xml` (`uses-feature microphone required=false`, `foregroundServiceType specialUse|microphone`).
- **Clasificador WAKE/LIGHT/DEEP (Fase C, sin ML):** `closeSmartWindow()` aplica reglas `Cole-Kripke/Sadeh` adaptadas: `WAKE` si `avg>=1.02` (`SMART_WAKE_THRESHOLD 1.0`) o `audioRms>=0.015` + `avg>=0.93`, si no `DEEP` si `avg<0.90` && `audioRms<0.015` else `LIGHT`. `confidence` distancia al umbral `0.3-0.95` + suavizado `2` ventanas consecutivas para cambiar `smoothedStage` (evita `DEEP→LIGHT` cada 30s). Persiste `level/stage/rawStage/confidence` por `smartWindow` (`hasAudio` flag) y se expone a JS vía `MovementModule` (`smartWindows[]` con `audioRms/Zcr` + `stage`).
- **SmartAlarm (Fase C):** `storage/SmartAlarmStorage.js` `smart_alarm_settings` `{enabled,hour,minute,windowMin 15|30|45}` + `services/SmartAlarmService.js` + nativo `SmartAlarmModule.kt`/`SmartAlarmPackage.kt` (`PACKAGE_ADDS` + `MainApplication.kt` `add(SmartAlarmPackage())`) guardan en `SharedPreferences smart_alarm`. `SleepForegroundService.closeSmartWindow()` check `isInSmartAlarmWindow()` (target `hour:minute` vs `startWall` de la ventana) → si `LIGHT` + `confidence>=0.6` log `SmartAlarm: momento favorable LIGHT` (TODO progresiva `sonido suave→vibración`). Card debug `SleepModeScreen` `Fase C` muestra `WAKE/LIGHT/DEEP*` `*estimación por reglas no diagnóstico` + `audio rms/zcr`.

## App architecture & main flows

### Bootstrap & navigation
- `App.js` → `AppProvider` (`context/AppContext.js`) wraps `navigation/AppNavigator.js` (single native stack, `headerShown: false`).
- Initial route: `Welcome` if no `userName`, else `Home`. Screens live in `screens/`; shared UI in `components/`.
- `AppContext` is the single source of state (profile, economy, pets, achievements, session, unlocks). It auto-saves to AsyncStorage (`storage/AppStorage.js`) on changes and restores on load. On mount it also restarts an active session (notification) and re-schedules the bedtime reminder.

### Sleep session flow
1. `SleepModeScreen.handleStartSleep` → requests `POST_NOTIFICATIONS` (Android 13+) + `ACTIVITY_RECOGNITION` → `setSleepSessionStarted(true)` → `startSleep()` writes `current_sleep_session` (`{startTime, active, unlockCount: 0, unlockTimes: []}`) → `startNotification` starts `SleepForegroundService` (persistent notification with elapsed time + unlock count).
2. `hooks/useSleepSession.js` ticks elapsed time every second from `startTime`.
3. Unlocks increment in `AppContext` while `sleepSessionStarted`; persisted by `updateUnlockState` (`services/SleepService.js`) and mirrored to the notification by `updateUnlocks`.
4. `finishSleep` → `finishSleepSession()` clears the active session; sessions < 0.5 h are discarded. **Siestas (0.5h ≤ hours < `STREAK_MIN_HOURS`=3):** se guardan en `sleep_history` con `isNap: true` pero 0 monedas, 0 XP, sin `unlockAchievements` (ni popup ni bonus), sin `setPetHappiness`/`setPetMood` (mascota intacta; `lastHappinessUpdate` sí se resetea), racha neutral ya existente. El conteo `sessions` para logros excluye siestas (`sleepHistory.filter(s => !s.isNap)`) en `SleepModeScreen` y `AchievementsScreen`; sesiones viejas sin `isNap` cuentan como normales. Otherwise: `calculateSleepRewards` → `SleepScoreService.calculateSleepScore` (score = 100 − (goal−hours)·10 − unlocks·5) → coins (score ≥90: 50, ≥75: 35, ≥60: 20, else 5) → XP via `LevelService.getXPFromQuality` (Excellent 25, Good 18, Fair 10, else 5; 100 XP per level) → session saved to `sleep_history` → streak vía `StreakService.computeStreakUpdate` (≥3h 1×/día) → `unlockAchievements` → navigate to `Results` (Results muestra tag `resultsNapTag` si `isNap`).

### Economy / gamification
- Coins: sleep rewards + achievement rewards; spent in PetShop.
- Level: `addXP` accumulates 100 XP per level.
- Pet mood: derived from sleep score (happy ≥90, normal ≥75, sleepy ≥60, sad).
- Pets: `PETS` catalog in `services/PetService.js` (cat is default/0; dog 100 … dragon 3000). Only pets with `available: true` can be bought; buying checks `canBuyPet`.
- Mascotas auto-detectadas por imágenes: `constants/PetImages.js` construye `PET_IMAGES` con `require.context` sobre `assets/pets/` (requiere `unstable_allowRequireContext` en `metro.config.js`; cat/dog tienen `require` estático como base segura). Exporta `AVAILABLE_PETS` (ids con los 4 moods `happy/normal/sleepy/sad`), y `PetService.js` deriva `pet.available` de ahí. Añadir una mascota = solo subir `assets/pets/<id>/{happy,normal,sleepy,sad}.png` y recompilar; borrar la carpeta la vuelve a "Próximamente".

### Storage (AsyncStorage keys)
- `sleep_pet_data` — profile + economy + settings (coins, streak, `lastStreakDateKey`, petMood, petHappiness, lastHappinessUpdate, userName, userAge, goalHours, goalType, selectedPet, ownedPets, language, level, xp, `preSleepBpm`/`bpmConfidence` persisten la última toma mientras la app vive).
- `current_sleep_session` — active session state (`{startTime, active, unlockCount, unlockTimes, preSleepBpm, bpmConfidence, bpmCapturedAt, bpmSource}`).
- `sleep_history` — array of finished session objects (cada entrada guarda `preSleepBpm`/`bpmConfidence`/`bpmCapturedAt`/`bpmSource` + `smartWindows[]` con `stage/confidence/audioRms` cuando existió Smart Sleep).
- `sleep_pet_achievements` — unlocked achievement ids.
- `sleep_reminder_settings` — `{enabled, hour, minute}`.
- `smart_alarm_settings` — `{enabled, hour, minute, windowMin: 15|30|45}` (`storage/SmartAlarmStorage.js` + `services/SmartAlarmService.js` + nativo `SmartAlarmModule` `SharedPreferences smart_alarm`).
- **Racha diaria:** `services/StreakService.js` `STREAK_MIN_HOURS=3` y `computeStreakUpdate` (≥3h cuenta 1×/día, siestas <3h neutras, día repetido no duplica, hueco ≥2 → 1). `AppContext` guarda `lastStreakDateKey` y re-hidrata `lastSleepSession = history[0]` (fix “No data yet” tras reinicio).
- **LAST NIGHT:** `HomeScreen` hidrata `lastSleepSession` desde `history[0]` (antes nunca se asignaba) y badge es dinámico por `mood` (Excellent/Good/Rest/Longer con colores verde/ámbar/rojo, oculto sin sesión) — era hardcodeado `Good Sleep!`.

### Translations
- `translations/es.js` and `translations/en.js`; selected via `services/TranslationService.js` (`getTranslations(language)`). All UI strings go through `t.*`.

### Bedtime reminder
- `SettingsScreen` saves `{enabled, hour, minute}` and calls `scheduleReminder`/`cancelReminder` (`services/ReminderService.js`).
- `ReminderModule.schedule` stores title/content in SharedPreferences and schedules a daily alarm via `AlarmManager.setAlarmClock` (exact) **solo si `canScheduleExactAlarms()`**; si no, hace fallback a `setInexactRepeating` (sin crashear). `ReminderReceiver` muestra la notificación y **re-agenda** la siguiente dosis. En Android 14+ requiere `SCHEDULE_EXACT_ALARM` (declarado en manifest/plugin); `SettingsScreen` muestra un enlace (`canScheduleExact`/`openExactAlarmSettings`) para activar "Alarmas y recordatorios" cuando no está otorgado.
- `AppContext` re-schedules on app start and language change if enabled. **No `BOOT_COMPLETED` receiver** → the alarm is lost on reboot until the app is opened again.
